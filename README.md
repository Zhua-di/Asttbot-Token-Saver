# 超节省群聊（astrbot_plugin_super_saver）

给 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 用的群聊调度插件：让机器人在群里**该说才说**，把 token 花在真正跟它说话的时候。

> 一句话定位：这是个**主动做减法**的插件。它会强行限制机器人的发言频率和发言时机，适合"希望机器人安静、省钱"的场景；如果你希望机器人在群里随时接话、活跃气氛，**请不要用这个插件**。

## 它解决什么问题

AstrBot 原生的群聊行为只有两档：

1. 不 @ 就不理人 —— 太冷，群友想跟它聊天得每次都 @；
2. 开主动回复（概率触发）—— 太吵，群友之间聊天它也插嘴，token 烧得飞快。

这个插件补上中间那一段：

- 群里有人**叫它的名字**就能接话，不必每次 @；
- 叫过之后有一段时间正常参与，**到点自动收声**；
- 收声之后群友自己聊天，它**不插嘴**；
- 一整套限流兜底，保证花费不会失控。

## 功能清单

| 功能 | 说明 |
|---|---|
| **关键词唤醒** | 群消息里出现配置的关键词，就当作在叫它，开启会话窗口 |
| **固定时长会话窗口** | 从被叫到那一刻开始计时（默认 5 分钟），**到点立刻结束**，中途聊天不会延长 |
| **插嘴判断** | 窗口内也不会无脑接话：先让模型判断"这句是不是在跟它说"，判 0 就不开口 |
| **愣神表现** | 窗口结束一段时间后再被叫醒，先让它说一句"啊？走神了"再接话，避免像机器一样秒回 |
| **回复间隔** | 两次回复之间至少间隔 N 秒（默认 6 秒），间隔内的消息直接丢弃、不排队 |
| **每分钟回复上限** | 每分钟最多回 N 条（默认 5 条），超了让它自己说一句"困了"然后静默 |
| **静默期** | "困了"之后保持沉默（默认 120 秒），期间**连 @ 也不回** |
| **判断次数上限** | 每分钟最多做 N 次插嘴判断（默认 10 次），控制额外开销 |
| **私聊不干预** | 私聊完全交给 AstrBot 原生逻辑，始终回复 |

## 工作流程

```
群消息到达
   │
   ├─ 静默期？ ────────────────── 是 → 直接丢弃（0 费用，@ 也不回）
   │
   ├─ 是 @ / 关键词 / 窗口内？ ── 否 → 不理会（群友自己聊天，不插嘴）
   │
   ├─ 距上次回复 < 6 秒？ ─────── 是 → 丢弃（0 费用）
   │
   ├─ 本分钟已回满 5 条？ ─────── 是 → 注入"困了"指令 → 回复一次 → 静默 120 秒
   │
   ├─ 是 @ 或关键词？ ─────────── 是 → 开启/重开窗口 → 正常回复
   │
   └─ 窗口内的普通消息
          ├─ 判断次数已满？ ───── 是 → 不插嘴（0 费用）
          ├─ 模型判断为"没跟它说" → 不插嘴
          └─ 判断为"在跟它说" ──→ 正常回复
```

## 安装

**方式一：面板上传**

AstrBot 面板 → 插件管理 → 安装插件 → 上传 `astrbot_plugin_super_saver-vX.Y.Z.zip` → 重启 AstrBot。

**方式二：手动放置**

解压后把 `astrbot_plugin_super_saver` 整个目录放进 `AstrBot/data/plugins/`，然后重启。

> 目录层级要正确：`data/plugins/astrbot_plugin_super_saver/main.py`。多套一层目录会导致插件加载失败。
>
> 如果实例里已经有功能相近的群聊唤醒插件，**请先停用其中一个**——两个插件都会修改同一个唤醒状态，会互相覆盖。

## 配置项

全部可在「插件管理 → 超节省群聊 → 配置」里修改。

### 唤醒与窗口

| 配置 | 默认 | 说明 |
|---|---|---|
| `keywords` | 大肥鱼 / 啥鱼 / 傻鱼 | 唤醒关键词，**子串匹配**（消息包含即命中） |
| `window_minutes` | 5 | 会话窗口时长（分钟），从被叫到开始计时 |
| `sliding` | false | 窗口内新消息是否延长窗口。关闭=固定时长、到点即止 |
| `reply_on_at` | true | @ 或引用它时也开启会话窗口 |

### 限流

| 配置 | 默认 | 说明 |
|---|---|---|
| `min_reply_interval_seconds` | 6 | 两次回复最小间隔（秒），间隔内的消息直接丢弃 |
| `max_per_minute` | 5 | 每分钟最多回复条数，0 = 不限制 |
| `sleepy_instruction` | 见配置 | 超限时的临时指令（让它用自己的语气说困了，不是固定台词） |
| `sleepy_seconds` | 120 | 说完困了后的静默时长，**期间 @ 也不回** |

### 插嘴判断

| 配置 | 默认 | 说明 |
|---|---|---|
| `judge_enabled` | true | 是否判断"这句是不是在跟它说"，关闭后退化为"窗口内每条都接" |
| `judge_instruction` | 见配置 | 判断用提示词，要求模型只输出 `1` 或 `0` |
| `judge_max_per_minute` | 10 | 每分钟最多判断几次，超出直接不插嘴（省钱） |

### 表现

| 配置 | 默认 | 说明 |
|---|---|---|
| `daze_enabled` | true | 窗口结束后再被叫醒时，先表现"愣神" |
| `daze_instruction` | 见配置 | 愣神时注入的临时指令 |

## 费用说明

这个插件的目标是"省钱"，但需要说清楚钱花在哪：

| 场景 | 是否调用模型 | 费用 |
|---|---|---|
| 窗口外、没叫它 | 否 | **0** |
| 距上次回复不足 6 秒 | 否 | **0** |
| 静默期内的消息 | 否 | **0** |
| 插嘴判断（窗口内普通消息） | 是，轻量 | 约 250 token/次，**判 0 也要付费** |
| 判断次数超过每分钟上限 | 否 | **0** |
| 说"困了"那一条 | 是 | 一次普通回复 |
| 正式回复 | 是 | 按正常对话计费 |

判断调用被封顶在 `judge_max_per_minute` 次/分钟，所以额外开销是可预期的。

粗略估算（以 deepseek-chat 为例，输入 ¥2/百万 token、输出 ¥8/百万 token，缓存命中更低）：20 轮上下文 + 5 条/分钟上限，5 分钟窗口的实际花费通常在 **¥0.05 上下**，具体取决于群活跃度。

## 限制与副作用（重要）

**请在使用前完整阅读这一节。**

### 1. 它是强制限流的，不是"建议"

- 到达 `max_per_minute` 后，它会**先说完"困了"再闭嘴**，接下来 `sleepy_seconds` 内**连 @ 都不回**；
- 间隔不足 `min_reply_interval_seconds` 的消息会被**直接丢弃**，不排队、不补发——群友会感觉"它没理我"；
- 窗口**到点即断**，不会因为你正在聊得投入而延长（除非把 `sliding` 设为 true）。

如果你不能接受"叫了它但它因为限流没回"，这个插件不适合你。

### 2. 状态存在内存里，重启即清零

会话窗口、限流计数、静默期、愣神标记都保存在插件内存中。**重启 AstrBot 后全部归零**：窗口消失，需要重新叫它；静默期也会立刻解除。

### 3. 关键词是子串匹配

`keywords` 里的词只要**出现在消息任意位置**就算命中。设置过短的词（例如单个"鱼"字）会在"摸鱼""鱼香肉丝"等无关话题上误触发。建议用 2 字以上、且不易出现在日常对话里的词。

### 4. 插嘴判断会误判

判断由当前对话模型完成，输入只有最近几句上下文 + 当前这句：

- **漏判**：确实在跟它说话，但被判为 0，于是它没回；
- **误判**：群友在聊自己的事，却被判为 1，于是它插嘴。

判断请求失败（网络/额度问题）时按"不插嘴"处理——宁可少说。

### 5. "困了"和"愣神"是提示词，不是硬编码

这两处通过注入临时系统提示实现，模型**偶尔可能不完全遵守**（比如仍然回答了用户的问题）。调强 `sleepy_instruction` / `daze_instruction` 的措辞可以改善。

### 6. 只在群聊生效

私聊完全透传，不受任何限制。别指望它在私聊里也"节省"。

### 7. 依赖 AstrBot 的内部行为

插件通过修改 `event.is_at_or_wake_command` 改变唤醒结果，依赖 AstrBot 4.24+ 的处理管线顺序。AstrBot 大版本升级后可能失效，需要关注更新。

### 8. 与其他唤醒类插件冲突

同时启用多个会修改唤醒状态的插件（主动唤醒、群聊增强等），行为不可预期。

### 9. 不处理消息内容安全

插件不审核内容、不拦截敏感词，这些仍由 AstrBot 原生能力和其它插件负责。

## 适用与不适用

**适合：**

- 群里人多、话题杂，不希望机器人对每条消息都开口；
- 想用便宜的模型长期挂群，需要把花费控制住；
- 希望"叫它才来、聊完自动退场"的拟人节奏；
- 接受"偶尔因为限流不回消息"。

**不适合：**

- 需要机器人当客服、随时响应每一条消息；
- 需要它主动热场、活跃气氛；
- 用本地小模型、完全不在意 token 消耗；
- 需要它在私聊里也节流。

## 常见问题

**Q：叫了它但没回？**

按顺序排查：① 是否在静默期（刚说过"困了"）；② 距上次回复是否不足 6 秒；③ 本分钟是否已满 5 条；④ 关键词是否写对（子串匹配）；⑤ 窗口是否已过期（默认 5 分钟）。

**Q：它老是插嘴 / 老是不插嘴？**

调 `judge_max_per_minute` 和 `judge_instruction`；或直接把 `judge_enabled` 关掉，退化为"窗口内每条都接"。

**Q：怎么让它更安静？**

优先调小 `max_per_minute`（影响最直接），其次缩短 `window_minutes`、加大 `min_reply_interval_seconds`。

**Q：怎么让它更活跃？**

把 `sliding` 设为 true（窗口持续续期）、调高 `max_per_minute`、调低 `min_reply_interval_seconds`。

**Q：日志在哪看？**

AstrBot 日志中带 `[WakeWindow]` 前缀的行，能看到窗口开启/结束、跳过原因、判断结果。
